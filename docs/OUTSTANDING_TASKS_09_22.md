## Tier 1 — ship-blockers (the five new Highs; fix before any multi-node or exposed deployment)

### ☑ T46 — Reconcile the lamport ceiling with the arithmetic around it (H-07) — S
> **Done 2026-09-22 (committed `0c3791a`).** Ceiling single-sourced as `ledger::service::LAMPORT_CEILING`, aliased by `p2p::union_merge` (the `ENVELOPE_KEYS`/`MAX_PARENTS` precedent); bound made **exclusive**, so the wire check and the ledger's adoption check reject the same set. One private `checked_lamport()` is the single enforcement point — it **refuses, never clamps** (clamping would re-issue an `(author, lamport)` pair and silently break M-18, which is the original defect's shape). Both stamp sites return `Result` and refuse before mutating; `stage_remote_directive` computes the adopted value early but **applies it only after validation and only on a real insert** — a duplicate was already folded in by the ingest that stored it, and `max+1` is not idempotent, so re-folding would let a replaying peer ratchet the clock one step per copy. Beyond brief: `reconcile_file`'s third inline stamp site routed through the same check, and boot `warn!`s when a file re-derives a clock at/above the ceiling. Bug-catch proof fired in both directions, including the restart half (the poison survives reboot via the file) and an ordering-only revert.
- **Why first:** it is the cheapest catastrophic attack in the register. One signed directive from an allowlisted peer permanently stops the victim authoring anything any peer will accept, **survives reboot**, and — because the poison directive is itself valid — replicates and poisons every node it reaches. Silent: mutations keep returning 200.
- **The defect:** `MAX_REMOTE_LAMPORT` caps what a node **accepts**; nothing caps what a node **stamps**, and there is a `+1` on each side of the accept bound. `grep` confirms no lamport ceiling exists anywhere in the `ledger` crate — the constant lives only in `p2p`, as an inbound check.
- **Change:** (a) clamp at the **stamp** sites — refuse to author above the ceiling rather than emitting an unreplicable directive; (b) reject an inbound lamport that would push the local clock past the ceiling instead of adopting it; (c) make the accept bound exclusive or reserve explicit documented headroom; (d) move the clock adoption **after** validation — today a directive that is ultimately rejected still poisons; (e) single-source the constant so `ledger` and `p2p` cannot drift again.
- **Files:** [union_merge.rs:50,276-284](../crates/p2p/src/union_merge.rs#L276-L284), [service.rs:3115](../crates/ledger/src/service.rs#L3115) (adoption `+1`), [service.rs:1856,1873](../crates/ledger/src/service.rs#L1856) (both stamp sites), [service.rs:1413-1416](../crates/ledger/src/service.rs#L1413-L1416) (boot re-derivation).
- **Verify:** ingest a directive at exactly `MAX_REMOTE_LAMPORT`, then assert a locally-authored directive still passes `validate_envelope` — **and again after a restart**. Property test: no reachable ingest path can push the clock past the ceiling. Bug-catch proof: against the unfixed code, the post-ingest local append must be rejected by the peer-side validator.

### ☑ T47 — A lossy boot must never reach a rewrite (H-08) — S/M
> **Done 2026-09-22 (committed `0c3791a`).** Chose **quarantine** over refuse-to-compact: `gl-node` compacts at startup to fold in a crash-window journal, so refusing would leave the journal permanently unfolded and block every later write — a boot brick by another name, which is what T35 was removing. New `quarantined: BTreeMap<String, Directive>` holds everything boot refused **outside** the DAG (not in the read model, account state, heads, or what is served). All **three** skip sites quarantine: the L-17 cycle skip, the T41 fan-in skip, and the `dag.insert` refusal arm. `compaction_directives()` serializes DAG ∪ quarantine, so the only production full-file write is lossless; `live_quarantine()` is one shared predicate so the operator's count can never disagree with what the next rewrite does. `reconcile_content` releases repaired records, so an operator's live fix needs no restart. Bug-catch proof: reverted, the audit's own proof test reports `left: 0, right: 6`.
- **Why:** this is the only finding in the series that **destroys financial records**. T35 replaced the L-17 boot brick with a skip and a warning telling the operator to repair the file; [main.rs:219](../crates/gl-node/src/main.rs#L219) compacts unconditionally before they can, and compaction serializes `self.dag.directives()` — which never contained the skipped directives. `remove_journal` then takes the sidecar. Strictly worse than the brick it replaced: a brick is recoverable by editing the file back.
- **Reachability is not exotic.** `directives_blocked_by_parent_cycles` is Kahn's and returns cycle members **plus all descendants**; a normal ledger is one parent chain, so pointing the oldest transaction's `openledger-parents` at the newest txid blocks the whole chain. Parents are envelope metadata, stripped before hashing — **no content id changes and no signature breaks**. The T41 fan-in skip fires the same way on **pre-T41 files at upgrade, with no attacker at all**, and so does any `dag.insert` refusal, which since L-14 includes `CycleCheckExhausted`.
- **Change:** never let a lossy boot reach a rewrite. Either (a) carry skipped directives through boot in a quarantine set that compaction re-serializes verbatim (preferred — preserves the records and stays tolerant), or (b) refuse to compact while any skip set is non-empty and surface a fail-closed operator error. Must cover **all three** skip sites, not just the cycle one.
- **Files:** [service.rs:1311](../crates/ledger/src/service.rs#L1311) (`cycle_blocked`), [service.rs:1355-1360](../crates/ledger/src/service.rs#L1355-L1360) (cycle skip), [service.rs:1377](../crates/ledger/src/service.rs#L1377) (fan-in skip), [service.rs:1385](../crates/ledger/src/service.rs#L1385) (insert refusal), [service.rs:2052-2056](../crates/ledger/src/service.rs#L2052-L2056) (compaction serializes the DAG), [main.rs:219](../crates/gl-node/src/main.rs#L219).
- **Verify:** the audit's proof, as a test — append six transactions through the public API, rewrite one `openledger-parents` line, reboot, **assert all six are still on disk**. Repeat for a pre-T41 over-fan-in file and for a `CycleCheckExhausted` file. Bug-catch proof: against the unfixed code the assertion drops to 0 transactions.

### ☑ T48 — Complete the CBOR pre-scan (H-09) — S
> **Done 2026-09-22 (committed `0c3791a`).** `supply_entry_count` is gone; one `walk()` now backs both scans, accounting for every top-level pair exactly one of three ways. `ArrayBound` gained `ElementKind::Struct { items }`, so `entries` is judged at its header and then **walked**. `scan_supply_frame` additionally requires each bound's key and rejects unknown/duplicate top-level keys (`SUPPLY_TOP_LEVEL_KEYS` = the wire struct's real field set). `MAX_SUPPLY_ENTRY_ITEMS` is derived from `ENVELOPE_KEYS`, so entry and envelope caps cannot drift. **Found and closed a second live hole the brief missed:** a 16 M-item payload hidden *inside* `entries` as its one truthfully-declared element — inside `MAX_SUPPLY_ENTRIES` by 256×, so no entry-*count* bound could ever see it (measured 805,306,600 B / 50.33× at HEAD). Measured after the fix: both attack shapes **peak 0 bytes**; honest supply 1.02×, honest want 1.82×.
- **Why:** it re-opens M-16, which T26/T43/T43b were written to close, and it is **silent** — the frame decodes *successfully* as an empty `Supply`, so there is no `BatchTooLarge`, no `FramePrescan`, no warning. Measured **805 MB peak for a 16 MB frame** (50.33×, the same factor `decode_memory.rs` records for the unguarded path); one budget unit per frame against a 100k per-connection budget, × 32 connections per peer ≈ 25 GB of transient heap from one key.
- **The defect:** `supply_entry_count` returns at the **first** `entries` key and never walks the rest of the top-level map, so a sibling key carries an unbounded array straight into serde's `Content` buffer. `scan_bounded_arrays` — the non-`Supply` arm — has no such hole. **The asymmetry is the bug:** the one variant T26 deliberately admits at 16 MiB is the one whose scan short-circuits.
- **Change:** walk every top-level pair and bound every array the frame carries, as `scan_bounded_arrays` already does; and reject `Supply` frames carrying unknown keys outright, since serde buffers them regardless of whether the struct wants them. Verified in vendored `serde-1.0.229/src/private/de.rs:859-886` that `TaggedContentVisitor::visit_map` buffers **every** pair, unknown keys included; ciborium's only guard is a 256-level *recursion* limit, not cardinality.
- **Files:** [cbor_scan.rs:560-573](../crates/p2p/src/cbor_scan.rs#L560-L573), [protocol.rs:375-378](../crates/p2p/src/protocol.rs#L375-L378).
- **Verify:** extend [decode_memory.rs](../crates/p2p/tests/decode_memory.rs) with the `{"type":"supply","entries":[],"z":[…]}` shape, asserting **both** rejection and bounded peak allocation — the existing tests measure only the two shapes T43/T43b fixed, which is why this survived. Bug-catch proof: the counting allocator must show the ~50× peak against the unfixed scan.

### ☑ T49 — Session bounds on anti-entropy, and a tick drain that cannot be held hostage (H-10, M-06, M-26, M-27, M-28, L-53) — M
> **Done 2026-09-22 (committed `0c3791a`).** New `SessionBudget` (deadline + frame counter + advert bounds) built once per exchange before the dial; `charge_frame()` is the only way to get a frame timeout and returns `min(io, time left)`, so a frame started near the deadline cannot get a fresh 30 s — H-10's exact mechanism. **Deliberately not a `timeout()` around the exchange future:** `apply_supply_entries` commits through `ledger_commit::commit_pending`, and dropping that future mid-commit *is* H-11 — so the deadline is checked at I/O boundaries instead. Page cap (512, derived 2× the honest worst case, charged before the page is examined so an empty page costs the same as a full one) and a 64 MiB byte budget charged once per distinct id across both lists. `^[0-9a-f]{64}$` via a shared `protocol::is_content_id`, which `union_merge`'s parents check now also calls, so the rule has one spelling; the advert is refused whole, not filtered. `open_bi_bounded` at both sites. Drain is `timeout_at(tick_deadline, join_next())` with stragglers **carried, not aborted** (aborting mid-commit is H-11 again), plus an RAII `InFlightGuard` bounding the set to one exchange per peer. Decode errors now render through a character-boundary-safe `BoundedSink` (the T48 fold-in). Money test drives the real `spawn_anti_entropy_loop` and asserts the healthy peer converges **after** the flood starts; bug-catch proof reverted → `client has 0 of 5 directives`.
- **Why:** ~40 bytes per frame from one allowlisted peer kills **all** anti-entropy with **all** peers, permanently, for the process lifetime — and anti-entropy is the designated correctness backstop that makes dropping gossip hints safe (T23). Silent: no error, no log, no health signal.
- **The defect chain:** `read_have_heads_advert`'s only exits are `more == false`, a read error, and the **distinct**-id cap. T41 changed `absorb_page` to count distinct ids — its own rustdoc and test say so (*"A peer replaying one page 10,000 times advertises ONE id"*) — which removed the only bound the loop had. `AntiEntropyTimeouts.io` is **per-frame** and every frame refreshes it. Then one never-returning task in the `JoinSet` means `while set.join_next().await.is_some() {}` never returns and `interval.tick()` is never reached again. **T41's dedup fix introduced this**; it is the clearest case for the bug-catch-proof note at the top of this file.
- **Change:** (a) a deadline around the **whole** exchange, not per frame; (b) a page counter and a byte budget on the advert loop (M-26 — the cap bounds count, not bytes, and nothing validates id length); (c) require `^[0-9a-f]{64}$` on every advertised id — the rule `openledger-parents` already has, and the cheapest fix for M-26; (d) a timeout on `open_bi` (M-27 — verified in vendored `noq-1.1.0/src/connection.rs:1007-1046` that `poll_open` pends forever against a peer advertising `initial_max_streams_bidi = 0`; the same hang in the gossip task leaks a `FetchCoordinator` permit and in-flight entry); (e) a client-side frame/round budget mirroring the server's `max_requests_per_connection` (M-28); (f) make the drain resilient — `join_next` with a timeout, or abort the `JoinSet` at the next tick — so one stuck peer can never stop the scheduler.
- **Files:** [anti_entropy_alpn.rs:624-648](../crates/gl-node/src/anti_entropy_alpn.rs#L624-L648) (`read_have_heads_advert`), [:592-598](../crates/gl-node/src/anti_entropy_alpn.rs#L592-L598) (`absorb_page`), [:422,451](../crates/gl-node/src/anti_entropy_alpn.rs#L422) (`open_bi`), [:565-567,579-581,658-699](../crates/gl-node/src/anti_entropy_alpn.rs#L579-L581), [p2p_service.rs:313-324,424-435](../crates/gl-node/src/p2p_service.rs#L424-L435), [anti_entropy.rs:24-51](../crates/p2p/src/anti_entropy.rs#L24-L51) (`compute_want`).
- **Verify:** the money test — a peer answering `more: true` with empty pages forever: assert the exchange aborts **and that the next tick still syncs a healthy peer** (the second half is the point; the first alone would have passed pre-T41). Plus a peer advertising `initial_max_streams_bidi = 0`; plus an advert of 255-byte ids asserting bounded resident bytes. Bug-catch proof: against the unfixed code the healthy peer never converges.

### ☑ T50 — Make `commit_in_flight` RAII (H-11) — S
> **Done 2026-09-22 (committed `0c3791a`).** `commit_in_flight: bool` → `Arc<AtomicU64>` holding the generation of the outstanding commit; `CommitInFlightGuard::arm()` is the **only** thing that sets it and its `Drop` releases with a generation-stamped `compare_exchange`, so a late drop cannot clear a later commit's flag. The guard is a private field of `PendingCommit` — the only handle `prepare` returns — so every exit drops it: cancellation, early return, panic/unwind. **A second bug closed on the way:** fixing only the flag would have let a cancelled caller release the `WritePermit` while its own `spawn_blocking` was still writing, so the next writer could take the gate and compact the journal out from under it. `commit_pending` now takes the permit **by value** and runs the hand-off inside `tokio::spawn`, awaiting only the `JoinHandle` (dropping a handle detaches, it does not abort) — the write completes, the receipt is folded in, and the permit releases after both. `prepare_or_recover`'s re-raise **stays**, documented: `recover_failed_commit` re-boots from disk, and doing that while another commit genuinely owns the files would discard state it is about to make durable. Bug-catch proof: all four tests fail with `CommitInFlight` on the *second* write. **Test-design catch:** the agent's first panic test passed under the revert (a panicking observer becomes a `JoinError` and the un-cancelled caller still recovers); rewritten to panic while holding the `PendingCommit`, the window only `Drop` covers.
- **Why:** one cancelled mutation permanently wedges **every** ledger write path — the three GraphQL mutations, the ALPN anti-entropy path (so **peer replication stops being persisted**), the file-watcher reconcile, and the shutdown compaction. Reads keep working and `/health` still returns `{"status":"ok"}`, so nothing surfaces it.
- **The defect:** `prepare()` sets the flag synchronously; the only two clears live **after** `spawn_blocking(...).await`; there is no `Drop` guard (`grep -rn "impl Drop"` over both files returns nothing). The `spawn_blocking` task is not cancelled, so the write still lands — only the bookkeeping is lost. `prepare_or_recover` then deliberately **re-raises** `CommitInFlight` without recovering, which makes it terminal.
- **Triggers are ordinary, not exotic:** (1) the node's **own** `TimeoutLayer` — vendored `tower-http/src/timeout/service.rs:138` returns `Poll::Ready(Ok(408))` and drops `inner`; the default is 30 s but `requestTimeoutSeconds` is legal down to **1 s**; (2) HTTP/2 `RST_STREAM`, a precise repeatable cancel primitive that needs no TLS because the port serves cleartext h2c (M-22/T55); (3) any panic on that path. Note the composition: **T54's quadratic `verify` is exactly what pushes a concurrent mutation past its timeout.**
- **Change:** make the flag RAII — a guard cleared on drop — or clear it explicitly on the cancellation path. Either way a wedged flag should become recoverable rather than terminal; consider whether `prepare_or_recover`'s deliberate re-raise is still the right call once the flag can no longer leak.
- **Files:** [service.rs:2081](../crates/ledger/src/service.rs#L2081) (set), [:2145,2182](../crates/ledger/src/service.rs#L2145) (the two clears), [:2017](../crates/ledger/src/service.rs#L2017) (the rejection), [ledger_commit.rs:100,155](../crates/gl-node/src/ledger_commit.rs#L100).
- **Verify:** issue a mutation, cancel the future mid-commit, assert the **next** mutation succeeds. Repeat for the 408 path (set `requestTimeoutSeconds: 1`) and for an h2 `RST_STREAM`. Bug-catch proof: against the unfixed code the second mutation returns `CommitInFlight` forever.

## Residuals opened or left by Phase 1 (new register candidates)

Phase 1 closed all five Highs. These are what the fixes could not close, or newly created —
recorded here rather than left as code comments, per the campaign's own lesson that
follow-up work is where regressions hide.

- **R-1 (Med) — a hard lamport ceiling is always reachable by peers (T46 residual).** An allowlisted peer sending `LAMPORT_CEILING - 2` still lands a receiver on `LAMPORT_CEILING - 1`, the last legal value, after which that receiver refuses to author — and that directive is legal, so it replicates. No choice of constant fixes this: *"every value I stamp is one my peers accept"* and *"no peer can exhaust my range"* cannot both hold below a finite cap. T46 changed the failure's **shape** (loud, local, named error, boot warning, never emits an unreplicable directive) but not its reachability. Closing it needs a **plausibility ratchet on adoption** — bounding how far one directive may advance the clock, not only where it may end up — which is a §3.4.2 change with its own failure mode (a long-offline replica would start refusing honest traffic). Compensating control meanwhile: the allowlist.
- **R-2 (Low) — compaction can now fail the size cap (T47 residual).** A compaction writes DAG ∪ quarantine, i.e. everything the file held rather than a subset, so a pathological file just under `MAX_LEDGER_FILE_BYTES` whose canonical form is larger could fail at `persist_atomically`. Fail-closed refusal, not data loss, and it is the pre-T35 behaviour — but it is a new way for a write to be refused.
- **R-3 (Low) — reconcile can adopt what boot quarantined (T47 residual).** Reconcile uses the DAG's own I8 check, not boot's Kahn pre-scan, so a hand edit on a cyclic file can pull cycle descendants into the DAG; the next boot re-quarantines them. No record is lost either way. This is the pre-existing reconcile-vs-boot asymmetry (see M-20), not something the quarantine introduced.
- **R-4 (Low) — ciborium's own peak on a type-mismatched frame (T48/T49 residual).** `{"type":"supply","v":"<16 MiB text>","entries":[]}` measures **80,000,161 B (5.00×)**, above the 4× the other shapes are held to. T49's `BoundedSink` stopped the multi-megabyte value being *propagated and logged*; the transient **allocation** inside ciborium/serde remains. Constant-multiple, not element-count, so M-16 family rather than H-09 — belongs with the frame caps.
- **R-5 (Low) — no global cap on concurrent anti-entropy exchanges (T49 residual).** `InFlightGuard` bounds the set to one exchange per peer, but nothing bounds exchanges *across* peers; a large allowlist still fans out unboundedly. Needs a semaphore sized against the allowlist. Tracked under M-26.
- **R-6 (Info) — T49's session deadline can now be tightened (closed by T50).** T49 deliberately used an I/O-boundary deadline rather than a `timeout()` wrapper because cancelling mid-commit was H-11. T50 made cancellation safe, so a real `timeout()` is now available as a tightening rather than a fix. Deliberate hand-off, documented at all three sites.
- **R-7 (Info) — naming and config surface.** `AntiEntropyTimeouts` now carries non-timeout bounds and keeps its name (renaming needs an edit in `main.rs`, which was off-limits during the concurrent wave). The new bounds are test-overridable but still have **no config surface** — T38 owes that wiring.
- **R-8 (Info) — two unreachable-today commit edges (T50 residual).** A runtime teardown that drops the spawned commit task before it runs returns `Io(JoinError)` without `recover_failed_commit`, so memory can be briefly ahead of disk (next boot re-derives; only reachable at process shutdown). And `mem::forget` on a `PendingCommit` still leaks the flag — not defensible against, not reachable from any call site.
- **R-9 (Med) — `meshId` should become required, but NOT in one step (T57 recommendation).** T57 closed M-31 on the default path, so an unset `meshId` no longer buys an unvalidated domain. Making it *required* would additionally buy L-23's semantic half — separating "can reach this mesh" from "is this mesh" — which validation cannot supply. **But the migration has a foot-gun the campaign's other breaking changes did not.** T36/T37/T41 refused a bad *value*, and the fix was to set a good one. Requiring `meshId` forces every deployment to choose a domain, and the only choice that preserves history is `meshId` = its current `swarmTopic` **byte for byte**, because a signature is verified by reconstructing the signed message with the verifier's own domain. An operator who does the obvious thing (`uuidgen`) silently invalidates every signature they and their peers already hold. Sequence it: (a) T57 as it stands; (b) a boot `warn!` when `meshId` is unset, whose remedy text leads with *"set it to your current `swarmTopic` verbatim"*, plus `meshId` shipped in `deploy/gl-node.docker.json`; (c) required a release later.
- **R-10 (Low) — an over-cap directive already on disk still loads at boot (T51 residual).** T51 applies the bean cap at reconcile but deliberately not at boot: boot loads records already in this ledger's history, and quarantining an over-cap directive there would drop a real transaction out of balances on a file a pre-L-02 build wrote legitimately. Such a record still loads, is still served, and is still refused by every peer. T51 stops this node *creating* more of them; it does not retire the ones that exist.
- **R-11 (Info) — CT-9 was not strengthened (T53 residual).** The invariant's own test still has a tie-free fixture and lives in `service.rs`, which T53 was not allowed to touch. Equivalent coverage now lives in `serialize.rs`, but CT-9 itself would not catch an M-24 regression. Add a tied pair (two same-day same-payee transactions) to its fixture.

## Tier 2 — the file-ingest path (its guards diverged from the wire's, and it signs what it adopts)

> **The theme.** L-11's fix made `reconcile_file` sign what it adopts. That turned the file path
> from a local-only concern into a **replication** concern: anything the file path accepts but the
> wire path rejects gets signed with this node's key, persisted, served, and then refused by every
> peer forever — permanent divergence plus perpetual re-Want churn, which is the H-03/H-06 shape
> reached through the file. The code names this outcome itself at
> [service.rs:396-399](../crates/ledger/src/service.rs#L396-L399). These two tasks close the gap.

### ☑ T51 — Reconcile/boot check parity (M-20, L-02, L-29, L-45) — S/M
> **Done 2026-09-22 (committed `8c985e2`).** New `validate_parent_txid_form` (L-29 — gives `parent_txid_is_well_formed` its **second** production call site), `validate_envelope_lamport_form` (M-20 format; mirrors the wire rule including the digit scan, because `"+7".parse::<u64>()` succeeds), `validate_file_envelope_form` (both file paths) and `validate_file_ingest_parity` (that plus `enforce_economic_bean_limit`). Guards sit **before** the envelope stamp and therefore before `sign_adopted_entry`; a rejection moves neither the clock nor a half-stamped envelope, and a `recording_signer` proves the id was never handed to the signer. A **second** bean-limit check runs on the *resolved* body immediately before signing — the guard chain measures the body as the file spells it, I2 then resolves the elided posting, and the resolved form is what peers measure; reverting that one alone fails its test while the plain over-cap test still passes, so both applications are independently load-bearing.
> **L-45 took the raw-text route, deliberately.** T47's quarantine holds `Directive` values, and a charset-rejected record never becomes one. Scoping down to "boot warns and skips" would have left the startup compaction rewriting the file with that block absent — **the H-08 shape re-entered through a different door**. So a second, narrow `quarantined_text: BTreeSet<String>` holds the exact source text of unparsable blocks and splices it verbatim onto the tail of every full rewrite. The canonical region above the tail is byte-for-byte what `full_file_serialize` produces, so T27/T29 determinism is untouched; what it gives up is `canonical_is_current` over that tail, bounded to text this node read from that same file and could not interpret. `parse_around_quarantined_text` skips a block **only** if its text is byte-identical to one already held — any other parse failure still refuses the whole reconcile, preserving L-30. Repair the account name and the block parses, is adopted normally, and stops being written back: the raw-text analogue of `release_quarantined_now_in_dag`.
> **Reverses a prior deliberate decision.** `test_boot_fails_closed_on_persisted_mixed_script_account` encoded T37's intentional brick; L-45 is the finding that this was wrong, so it was replaced by the tolerant-boot test, keeping its "operator must see the line and the character" assertion. **Scope decision recorded in-source:** the bean cap applies at reconcile but **not** at boot — boot loads records already in this ledger's history, and quarantining an over-cap directive there would drop a real transaction out of balances on a file a pre-L-02 build wrote legitimately. Bug-catch proofs fired six times, including the L-29 divergence walked through the **real** `validate_supply_entry` + `verify_remote_signature` with a real Ed25519 signature.
- **Why:** three guards the wire and local-API paths enforce are simply absent from `reconcile_content`, and one is absent from boot. M-19 (T52) makes this reachable in **every** deployment, including those that set the documented opt-out.
- **What is missing, precisely:**
  1. `enforce_economic_bean_limit` — the open half of **L-02**. Nothing else bounds body length; the parser caps charsets, not lengths. The oversized entry is signed and then refused at [union_merge.rs:137-143](../crates/p2p/src/union_merge.rs#L137-L143) forever.
  2. **Any parent-txid form check** — **L-29's rule, absent on the file path.** `parent_txid_is_well_formed` ([service.rs:224](../crates/ledger/src/service.rs#L224)) has exactly **one** production call site, `:3082` in `stage_remote_directive`. Reconcile (`:2554`) and boot (`:1378`) call only `validate_parent_fan_in`, which is a *count* check ([service.rs:562-573](../crates/ledger/src/service.rs#L562-L573)). `LedgerDag::insert` does not check form either. Parents are envelope metadata, so a hand edit changes no content id.
  3. **Any lamport format or range check** — `:2604-2607` silently ignores an unparseable value, and a file lamport of `u64::MAX` sets the boot clock to `u64::MAX`, destroying the `(author, lamport)` uniqueness T31 restored. **Coordinate with T46**, which owns the ceiling.

- **Note the ordering constraint:** the checks must refuse the entry **before** it is signed, not after.
- **Files:** [service.rs:2479-2704](../crates/ledger/src/service.rs#L2479-L2704) (`reconcile_content`), [:2554,2604-2607,2642](../crates/ledger/src/service.rs#L2554), [:1290-1294,1378](../crates/ledger/src/service.rs#L1378) (boot), [:224,562-573](../crates/ledger/src/service.rs#L224), [dag.rs:176-190](../crates/ledger/src/dag.rs#L176-L190).

## Tier 3 — cost, determinism, and the HTTP edge

### ☑ T53 — Total serialization order (M-24) — S
> **Done 2026-09-22 (committed `8c985e2`).** New `canonical_order()` replaces the inline comparator: decorate-sort-undecorate on `(date, type priority, stable sort key)`, then sorting **only** the equal-primary runs by `(content id, emitted bytes)`. The content id is the only valid tiebreak — arrival order, file position and the envelope Lamport are all replica-local (M-10). The **second** component is load-bearing because envelope metadata sits outside the content id, so two entries can share an id and still emit different bytes; removing it fails exactly one test and nothing else. Primary ordering deliberately untouched (boot, `reconcile_content` and T44's journal all read it) — guarded by `test_m24_tie_free_file_is_byte_identical_to_the_pre_fix_serializer`, which compares against the verbatim pre-fix output. 120-permutation test over a set with two independent tie runs. **Net cheaper:** the old comparator built two key strings per comparison (O(n log n) allocations); decoration builds n, and the content-id hash is computed only for members of a tie run, so a tie-free file pays zero new hashing.
- **Why:** it breaks the project's own I7/C4 guarantee, with **no attacker and ordinary data**. `stable_sort_key` ([serialize.rs:68](../crates/ledger/src/serialize.rs#L68)) is `narration|payee` for transactions and `account` for opens — omitting postings, amounts and currency lists — and `sort_by` is stable, so ties fall back to `LedgerDag::insertion_order`, i.e. **arrival order**. Proven for two "Starbucks/Coffee" transactions with different amounts and for two same-date `open Assets:Cash` with different currencies. Permanent: a reboot re-derives insertion order from the file's own order. Directly contradicts the assertion at [service.rs:6348](../crates/ledger/src/service.rs#L6348) (*"CT-9: After convergence, .bean files must be byte-identical (C4/I7)"*).
- **Change:** append the content id to the key — exactly as `accounts::LifecycleKey` already does. It is total by construction and already the pattern in-tree.
- **Files:** [serialize.rs:68](../crates/ledger/src/serialize.rs#L68), CT-9 at [service.rs:6348](../crates/ledger/src/service.rs#L6348).

The in-code comment reasons only about incidental overflow and concludes "the table drains within one window" — but an attacker holds the table at the cap by touching 65,536 keys once per 60 s window (~1,100 cheap requests/s, each well under the per-bucket limit), and flood traffic from any further key **never grows the table**. A single routed IPv6 /48 supplies exactly 65,536 /64 keys. **Change:** fail closed under a shared overflow budget, or evict expired-soonest — never admit free.
- **M-30 — `trustedProxies` misses a dual-stack peer.** `bucket_key` normalizes IPv4-mapped IPv6 ([:267](../crates/gl-node/src/rate_limit.rs#L267)); `client_ip` does not ([:135](../crates/gl-node/src/rate_limit.rs#L135)). With `bindAddress: "::"` an IPv4 proxy arrives as `::ffff:172.18.0.9`, never equal to `V4(172.18.0.9)` → XFF discarded → **every client behind the terminator shares one 60/min bucket**, i.e. M-04 re-created by a type mismatch. - **M-22 — cleartext h2c on the GraphQL port** *(moved here from T56, which shipped the advisory fix)*. T56's `h2` bump removed the live advisory, so what remains is attack-surface reduction: a whole second protocol implementation reachable pre-auth, below the axum stack where the API key, Host guard and limiter do not reach. It is also T50's cleanest cancel trigger (`RST_STREAM`).
  - **⚠ The obvious fix is a silent no-op — do not ship it alone.** `Builder::http1_only()` is documented *"Does not do anything if used with `serve_connection_with_upgrades`"*, and that is exactly what [http_server.rs:179](../crates/gl-node/src/http_server.rs#L179) calls. Confirmed in the vendored source: `serve_connection` (auto/mod.rs:~228) matches on `self.version`, but `serve_connection_with_upgrades` (auto/mod.rs:256) goes **unconditionally** to `ReadVersion` and never consults it. Adding `http1_only()` here would leave h2c fully enabled — the H-05 shape (an opt-in limit that never fires) all over again.

That drops HTTP upgrade support, which is safe today — grep confirms **no WebSocket route and no upgrade handler**; the only routes are `/graphql` (GET GraphiQL + POST) and `/health`. Alternative if upgrades are wanted: keep the sniffing builder and reject the h2 preface explicitly.
  - **Verify:** a client sending the h2 preface (`curl --http2-prior-knowledge`) is refused rather than served; T22's nine `http_server` tests still pass — the serve-loop change is under them, so they are the regression net. Bug-catch proof: with `http1_only()` but `serve_connection_with_upgrades` restored, the preface test must **fail**, proving the test detects the no-op.
- **M-33 — no per-IP connection cap.** `accept_with_permit` takes the permit **before** `accept()` ([http_server.rs:223-233](../crates/gl-node/src/http_server.rs#L223-L233)) — deliberate and correct against a flood — but the cap is **global only**, with no analogue of the ALPN side's 32-per-peer. H-01's DNS-rebinding read, closed for `/graphql` by T19, is still open here, plus an unauthenticated unmetered `ledger.read()` per request.

### ☑ T58 — P2P cost and robustness sweep (L-01, L-33, L-34, L-38, L-39, L-53, L-54) — M
> **Done 2026-09-22 (committed `3d5ff71`).** **L-01/L-33:** new `SupplyBudget`/`build_supply` budgets *while* collecting — a 1,024-id Want now serializes exactly 256 entries (was 1,024) — and the reply is **byte-identical** to the old collect-then-truncate output, so H-02's re-Want progress guarantee is untouched. **L-34:** `RefusalCache` keyed by **(peer, id)**, not id alone: the content id covers only the economic body, so id-only keying would let any allowlisted peer suppress a directive node-wide by serving a corrupt copy first. 10-min TTL, 16,384 total / 4,096 per peer, never refreshed. Classification is an exhaustive `match` (a new error variant won't compile unclassified): content-determined refusals cached; account-wait, orphans, DAG/cycle verdicts (L-40 shows they clear), `LamportCeiling`, I/O and `CommitInFlight` **never** cached; stage refusals recorded only if the batch commit succeeded. The misclassification mutation (caching account-waits) fails its guard test. **L-38:** poisoned mutexes recovered, not panicked. **L-39:** global 256 MiB / per-peer 32 MiB in-flight frame-body budget, charged per capacity growth before allocation (within 2× of bytes received), refused rather than awaited (waiting would re-create H-10); outbound reads unmetered so inbound peers can't starve our own replication. **L-54:** amortized TTL sweep via an `oldest_buffered_at` bound — 1,000 re-buffers, 0 full passes. **L-53** confirmed already closed by T49.
- **L-01 / L-33 — `collect_supply` trims at the wrong end.** [anti_entropy_alpn.rs:706-718](../crates/gl-node/src/anti_entropy_alpn.rs#L706-L718) serializes and hashes *every* matched directive for a Want of up to 1,024 ids under the ledger read lock, then `truncate_supply` discards all but 256 / 15 MiB. A ~68 KiB request frame costs up to ~64 MiB of allocation (the 09/01 report's "1 GiB" is now wrong — the 64 MiB file cap bounds it), and 32 connections per peer sustain it concurrently. **Change:** budget while collecting, not after. This is L-01's open Want arm; the advert arm is already closed.
- **L-34 — no refusal cache.** `compute_want` just diffs, so any permanently-rejected directive — the M-09 residual, anything in the M-20 class — is re-Wanted, re-transferred and re-validated **every tick forever**, with its orphans churning on the 1 h TTL. **Change:** a bounded negative cache on the anti-entropy path, mirroring `FetchCoordinator`'s.
- **L-39 — `ConnectionLimiter` bounds count, not bytes:** 256 connections × up to 16 MiB in-flight frame body ≈ 4–8 GiB of legitimately-shaped buffers. (M-16's other half; T48 owns the pre-scan.)
- **L-38 — `fetch_coordinator` panics on mutex poisoning.** `.expect()` at [fetch_coordinator.rs:149,158,177,222,230](../crates/gl-node/src/fetch_coordinator.rs#L149) inside the gossip-loop task, where everywhere else in the tree uses `unwrap_or_else(|p| p.into_inner())`.
- **L-53 — `Announce.id` is unvalidated** and used as a negative-cache key (bounded to ~16 MB by iroh-gossip's 4096-byte frame default). Fold into T49's `^[0-9a-f]{64}$` rule if that lands first.
- **L-54 — `drain_orphans` re-runs an O(n) TTL sweep per re-buffer** under both write locks.

> **Done 2026-09-22 (committed `3d5ff71`).** **L-41:** overflow-proof bound (`payload_length > len - cursor`) and an over-wide length saturates, so every header claiming more bytes than exist — `usize::MAX`, a cursor-overflowing length, a 40-digit number — is a torn tail, never a panic inside `recover_failed_commit` under the write lock. **L-44:** mode set on the temp file's **handle** before sync+rename; the path chmod is gone. ## Suggested landing order & regression-test manifest

**T56 first** — it is one command plus a one-word CI fix, and it turns the build green so every later
task lands against a trustworthy signal. Then Tier 1 as five focused PRs (**T46 → T47 → T48 → T50 →
T49**, cheapest-and-most-severe first; T49 is last because it is the only M-sized one). Tier 2 then
Tier 3 can proceed in parallel; Tier 4 is scheduled.

**T45 interaction:** wave C (wire v2) can run in parallel with Tier 1. **Waves A+B should wait for
T46 and T51**, which both touch envelope fields Format v2 re-specifies, and **T57 is a prerequisite
for Facet B** (it constrains `mesh_id`, the one signed field L-06 still leaves open).

Tests that must exist by the end of Tier 1:

1. Ingest at `MAX_REMOTE_LAMPORT` → a locally-authored directive still validates at a peer, **across a restart** (T46 / H-07).
2. Patch one `openledger-parents` line → reboot → **all transactions still on disk**; same for a pre-T41 over-fan-in file and a `CycleCheckExhausted` file (T47 / H-08).
3. `{"type":"supply","entries":[],"z":[…]}` rejected **and** peak allocation bounded, measured with `decode_memory.rs`'s counting allocator (T48 / H-09).
4. A peer answering `more: true` with empty pages forever → exchange aborts **and the next tick still syncs a healthy peer**; plus `initial_max_streams_bidi = 0`; plus a 255-byte-id advert with bounded resident bytes (T49 / H-10, M-26, M-27, M-28).
5. Cancel a mutation mid-commit → the next mutation succeeds; repeated for the 408 path at `requestTimeoutSeconds: 1` and for an h2 `RST_STREAM` (T50 / H-11).

Every one of the five needs its **bug-catch proof** — revert the fix, watch the named test fail,
restore — and for T48 and T49 the proof must be run against the *T43/T41 code that introduced the
regression*, not against the pre-T26 baseline.
